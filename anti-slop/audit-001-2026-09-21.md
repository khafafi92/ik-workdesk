# Audit anti-slop Dashboard IK WorkDesk

> Pembaruan 22 September 2026: perbaikan temuan 1 sampai 5 dan bukti pengujiannya tersedia di [laporan tindak lanjut](follow-up-001-2026-09-22.md). Isi di bawah merekam kondisi sebelum perbaikan.

Tanggal: 21 September 2026. Mode: **After**, sesuai permintaan audit atas Dashboard yang sudah ada. Target utama: Dashboard Filament `/panel`, bukan halaman legacy `/dashboard`.

**Kesimpulan: ada lima kelompok temuan yang perlu ditangani. Audit ini berbasis kode, perhitungan kontras, dan render HTML server. Verifikasi visual di browser belum dapat dilakukan.** Tidak ada kode aplikasi, desain, atau data bisnis yang diubah.

## Cakupan dan bukti

- Membaca Blade Dashboard, query data, dua stylesheet yang dimuat panel, dan aturan anti-slop core/UI/human/layoutmobile serta panduan teks.
- Browser automation mengembalikan `No browser is available`. Tidak ada klaim screenshot, pengukuran computed styles, klik mouse, pemeriksaan console, atau simulasi viewport yang sudah dijalankan.
- Menjalankan enam tes dengan **50 assertion**, semuanya lulus. Tiga probe audit mereproduksi perilaku saat ini; kelulusan probe bukan berarti UI bebas masalah. Tiga tes lainnya adalah tes Dashboard bawaan.
- Probe memakai SQLite `:memory:` dengan guard sebelum migration, data sintetis, dan mail/notification fake. Database bisnis tidak disentuh.
- Memakai `contrast-check.py` dari skill untuk menghitung pasangan warna CSS. Urutan stylesheet diverifikasi di `app/Providers/Filament/AdminPanelProvider.php:65`: theme terlebih dahulu, lalu ui-polish.
- `DESIGN.md` belum tersedia. Pembacaan sementara dari sumber: Dashboard operasional untuk staf internal, tampilan ringkas, warna status untuk pekerjaan, dan gerakan terbatas. Ini observasi kode, bukan arah desain baru yang disetujui pemilik. Penilaian identitas visual dan ENERGY/RHYTHM/MOTION tetap belum diverifikasi.

## Temuan bernomor

### 1. HIGH: beberapa teks kecil tidak memenuhi kontras anti-slop

**Aturan: R-25. Alasan:** teks berukuran 10–11 px membutuhkan rasio minimal 4,5:1; lima pasangan warna dari CSS berada di bawah batas tersebut.

| Elemen | Teks / latar | Rasio |
| --- | --- | --- |
| Waktu reminder dan pesan kosong | `#9699a6` / `#ffffff` | 2,84:1 |
| Angka reminder terlambat | `#e2445c` / `#fdebee` | 3,51:1 |
| Badge Resolved | `#ffffff` / `#008f5d` | 4,13:1 |
| Badge In Progress | `#ffffff` / `#bd7600` | 3,65:1 |
| Tautan Buka Reminder | `#0073ea` / `#e5f1fd` | 3,95:1 |

Sumber: `public/css/filament/admin/workdesk-theme.css:836`, `:917`, `:929`, `:958`; `public/css/filament/admin/workdesk-ui-polish.css:1155`, `:1169`. Ukuran badge ditetapkan pada theme `:694`. Override tipografi umum tidak menargetkan teks kecil reminder secara langsung. Rasio ini dihitung dari deklarasi CSS, belum dari warna hasil render browser.

**Usulan:** gelapkan teks metadata, pilih warna teks/latar status yang memenuhi rasio, dan periksa kembali semua state. Pertahankan label status sehingga makna tidak hanya mengandalkan warna.

### 2. HIGH: angka reminder terlihat seperti total, tetapi berhenti pada lima

**Aturan terkait: R-17 dan C-5. Alasan:** angka berasal dari data nyata tetapi tidak mewakili jumlah kategori yang tersirat oleh label.

`getDashboardData()` mengambil maksimal lima reminder per kategori. Blade menghitung koleksi yang sudah dibatasi itu, kemudian menampilkan tiga item pertama. Dengan delapan data sintetis pada masing-masing kategori Hari Ini/Akan Datang/Terlambat, hasilnya **angka 5 dan tiga judul**. Tidak ada teks “3 dari 8” atau penjelasan batas daftar.

Sumber: `app/Filament/Pages/Dashboard.php:157`; `resources/views/filament/pages/dashboard.blade.php:88`, `:91`, `:105`, `:108`, `:122`, `:125`. Reproduksi: `evidence/DashboardAuditTest.php`, hasil `evidence/reminder-evidence.json`.

**Usulan:** hitung total dengan query terpisah sebelum limit; tetap ambil tiga item untuk preview. Tampilkan “3 dari 8” dan tautan menuju kategori yang sesuai. Ini kesalahan penyajian ringkasan, bukan tuduhan data dibuat-buat.

### 3. HIGH: area sentuh tautan Dashboard belum memenuhi patokan 44 px

**Aturan: R-03. Alasan:** CSS tautan masih mengutamakan kepadatan desktop tanpa menetapkan area sentuh mobile yang memadai.

- Tautan “Lihat Semua” pada panel memakai `min-height: 2rem`, sekitar 32 px pada ukuran root standar 16 px, tanpa padding vertikal.
- “Lihat semua” pada kartu statistik memakai teks 10 px tanpa padding atau minimum area sentuh.
- “Buka Reminder” memakai teks 11 px dengan padding vertikal 7 px, tanpa minimum tinggi 44 px.
- Media query 760 px mengubah susunan dan lebar tombol, tetapi tidak menambah tinggi minimum area sentuh.

Sumber: `public/css/filament/admin/workdesk-ui-polish.css:940`; `public/css/filament/admin/workdesk-theme.css:836`, `:986`, `:1030`.

**Usulan:** tetapkan area interaksi minimum 44 × 44 px pada layar sentuh, dengan jarak antaraksi. Angka 44 px adalah patokan skill anti-slop yang digunakan di sini; temuan ini bukan klaim hasil sertifikasi WCAG. Tinggi aktual, spacing, dan kondisi zoom masih perlu diukur di browser.

### 4. LOW: judul periode dan label tindakan kurang spesifik

**Aturan terkait: R-15 dan C-5. Alasan:** pengguna perlu memahami cakupan angka dan tujuan tautan dari teks yang tampil.

H1 berbunyi “Ringkasan kerja hari ini”, tetapi total tiket/work logs dihitung lintas waktu; daftar terbaru juga tidak dibatasi hari ini. Probe memasukkan tiket bulan sebelumnya dan tiket tersebut tetap masuk ke total serta tabel. Ini bisa disalahpahami sebagai jumlah transaksi hari ini.

Empat tautan memakai “Lihat semua”/“Lihat Semua” untuk dua tujuan berbeda. Nama programatis tautan tidak menyebut jenis datanya. Konteks visual mungkin cukup bagi sebagian pengguna, tetapi label seperti “Lihat semua tiket” lebih jelas saat tautan dibaca terpisah. Ada pula campuran label Indonesia/Inggris, seperti Request, Subject, Judul, Progress, dan Terlambat, tanpa pedoman istilah tertulis.

Sumber: `resources/views/filament/pages/dashboard.blade.php:26`, `:36`, `:51`, `:147`, `:175`; `app/Filament/Pages/Dashboard.php:60`, `:97`, `:175`.

**Usulan:** beri judul umum “Ringkasan pekerjaan” dan label periode pada setiap ringkasan, atau benar-benar batasi data harian jika itu maksud bisnisnya. Gunakan label tindakan spesifik dan sepakati istilah; nama produk/modul tidak perlu diterjemahkan otomatis.

### 5. LOW: judul pekerjaan dipotong tanpa akses langsung ke rincian

**Aturan terkait: C-2, C-4, dan R-20. Alasan:** Dashboard operasional sebaiknya memudahkan pengguna mengenali pekerjaan dan membuka tindakan berikutnya.

Subject tiket dan judul work log dipotong di server pada 34 karakter. Baris hanya berisi teks; nomor tiket/judul tidak berupa tautan. Pada fixture judul panjang, render HTML tidak memiliki teks lengkap maupun tautan rincian pada baris. Pengguna harus membuka daftar umum dan mencari ulang. Judul reminder juga memakai ellipsis satu baris tanpa tautan per item.

Sumber: `resources/views/filament/pages/dashboard.blade.php:155`, `:156`, `:183`, `:184`; `public/css/filament/admin/workdesk-theme.css:949`. Reproduksi tiket: `evidence/DashboardAuditTest.php`.

**Usulan:** jadikan nomor/judul tautan ke rincian yang tetap mengikuti permission, lalu tampilkan judul dua baris atau sediakan cara mengakses judul lengkap dengan keyboard dan sentuhan. Ini peluang peningkatan alur, bukan tombol mati: sel tabel saat ini memang bukan kontrol interaktif.

## Hal yang sudah baik

- Struktur utama berisi data pekerjaan dan reminder yang relevan, tanpa statistik pemasaran, testimonial rekaan, atau ilustrasi pengisi.
- Pesan kosong untuk tiga kategori reminder dan dua tabel benar-benar dirender; diverifikasi dengan tes.
- Tujuan Service Desk, Work Logs, dan Reminders mengembalikan HTTP 200 untuk fixture administrator. Ini pemeriksaan HTTP, bukan klik browser.
- Badge status memuat teks. Makna status tidak bergantung pada warna saja.
- CSS memiliki reflow satu kolom di bawah 760 px, overflow tabel dalam wrapper, dan aturan reduced-motion. Keberadaan aturan ini belum membuktikan semua viewport berhasil.
- Override akhir menghapus bayangan dan gerak dekoratif panel. Tidak ada dasar untuk menyimpulkan semua kartu, font Inter, atau warna biru harus diganti hanya karena umum digunakan.
